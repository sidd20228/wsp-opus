An independent replication of Sparks of Weight-Space Programming by Rikiya Takehi, Jayden Teoh, Alex Zhang and Omar Khattab (MIT CSAIL, 2 November 2026), using their released logs. This is not affiliated with the original authors.

TL;DR

The original post found that GPT-6 Astra can read and write neural network weights. It can tell what a network was trained to do from the raw numbers alone, and write small game-playing networks from all-zero weights. I re-ran its eight experiments with Claude Opus 5.5 in place of Astra: the same prompts, word for word, no tools of its own, and the evaluation re-checked against Astra's released artifacts first.

So far, the simpler results replicate. From the weights alone, Opus names the game behind all 4 game-playing networks and the shape behind all 3 diffusion models. Without any training, its edit of 25 weight entries fixes a failing car policy on 1,024 of 1,024 test episodes, changing 1.33% of its weights. Its MinAtar networks, written from all-zero weights, score 511.7 on Breakout, against Astra's 517.4 and a 100M-step PPO agent's 15.8.

The harder ones are mixed. Opus usually finds a language model's copy heads but guesses its training corpus poorly. Twice, it answered without running a single line of code. Its Go network written without passes loses more often than Astra's. The sycophancy and math experiments are still running.

Weight-Space Programming

The original post asks a simple question with large consequences. When a frontier language model looks at the raw numbers of a neural network, with no training loop, no forward pass and usually no code, can it work out what the network does? And can it write the numbers itself? The authors call this weight-space programming. In eight experiments, GPT-6 Astra named the game a policy was trained on and the shape a diffusion model draws. It also found the copy heads of a transformer from its middle blocks, repaired a broken car policy with a one-shot edit, and wrote game-playing networks from zero weights. It even edited Qwen3.5-0.8B to escape the reasoning loops its model card warns about.

A result this surprising should be checked with a second model. The authors released the logs that make that possible: every prompt, every reply, the networks and the evaluations. So I ran the same experiments with Claude Opus 5.5 (claude-opus-5-5). The goal is not a leaderboard. It is to see which of the sparks are a property of frontier models in general and which belong to one model.

How Opus was run

The original ran Astra through the Codex CLI with every tool turned off. I ran Opus through the Claude Code CLI in the same way. Each turn is one headless claude -p call, or claude -p --resume to continue a conversation, with these settings:

  • No tools: --tools "", with no MCP servers, settings, skills, slash commands or browser.
  • Same instructions: the original's one-line system prompt, "Answer the user's request."
  • Clean, empty environment: each conversation runs in an empty folder with a minimal environment.
  • Same effort: the original's effort level for each experiment (high, xhigh or max).

Every turn's event stream is audited. So far, all 310 completed turns are tool-free. Where an experiment allows code, Opus writes one fenced block per turn, and my harness runs it in a Modal sandbox with no network, then returns the printed output in the original's exact format. GPU work (the car simulator, Go, the Gemma fine-tunes, Qwen evaluation) also runs on Modal.

Before any Opus number was compared, every evaluator was checked against Astra's released artifacts. Re-applying Astra's Exp 4 edit to the released weights changes exactly the same 6,073 weights, and its edited car still wins 1,024 of 1,024 episodes in our simulator, matching the original's logged trajectory step for step. Astra's MinAtar networks score within 1.3 standard errors of the published means. Astra's Go networks reproduce their published head-to-head results against the released same-size PPO networks. Our Qwen evaluation reproduces Astra's edited model to within about a point on GSM8K and IFEval and 3 points on MATH-500. Every deviation from the original setup is listed in results/deviations.md.

What is different. Opus 5.5's knowledge cutoff (June 2026) is before the original post, so it cannot have seen the answers. Claude Code adds about 1,400 tokens of its own context that the system prompt does not remove. The runs use a claude.ai subscription, so they pause at usage limits and then resume the same conversation. Where the original kept models or opponents private (the Go opponents, the Gemma fine-tunes), I rebuilt them from the released code and compare Astra and Opus on the rebuilt ones.

Can LLMs understand model behaviors from weights?

EXPERIMENT 1

Can Opus tell which game the network was trained on, just from the weights?

Each of four PPO policies, a small MLP for one Atari-like game, is printed in full as text. Opus gets the network and a description of its input format, and must name the game. This is an open answer, not multiple choice. The prompt is roughly 80,000 tokens of numbers.

EXPERIMENT 2

Can Opus tell what the diffusion model will generate?

Three small DDPMs (an MLP of 23,824 weights each) were trained on 12×12 images of one shape each. Opus sees only the weights and must say what the images look like and draw one. The original found that Astra's drawings were outlines, which is what the models really generate, even though a model guessing from priors would draw filled shapes.

EXPERIMENT 3

Can Opus tell what a language model learned, from the middle of the network alone?

This is the first experiment with a sandbox. A 4-layer, 6-head character-level transformer (7.16M weights) was trained on Python source, romaji or English Wikipedia. Opus gets only the four middle blocks: no embeddings, no output layer, no tokenizer. Using up to 100 Python runs over the weights, with no forward pass allowed, it must name the corpus and label each of the 24 heads. Astra got the corpus right in 6 of 6 conversations and named the measured copy heads exactly every time.

Two answers with no code run. In two of the six conversations, Opus never ran any code. In one, its first reply contained 272 imitation tool calls in its own tool-use syntax, together with outputs it made up, followed by a final answer. In the other, it wrote a detailed analysis with eigenvalues and composition scores "as if" code had run, again with no code block. The original harness treats a reply without a ```python block as the final answer, so both conversations ended after one turn. I keep them and report them, but their numbers come from nowhere. Astra never did this. This looks like a side effect of running a model trained on tool use with its tools switched off.

Can an LLM write neural network weights?

EXPERIMENT 4

Can Opus fix a failing network by editing its weights?

A Kinetix car policy (an MLP of 171,536 weights) fails on a ramp level: it stalls before the goal on every test episode. Opus sees the scene, a traced failing episode and all the weights as scaled integers, about 435,000 tokens in total. It may reply only once, with an edit written in a small edits language. No simulator, no second try.

EXPERIMENT 5

Can the LLM write weights from scratch?

The networks start with every weight at zero. Opus gets only the observation format of a MinAtar game and the network's shape, a 600-32-32-6 MLP, and in one reply must write every nonzero weight, using an edits language. It never sees the game run. The networks are scored over 1,000 episodes.

Real-world relevant scenarios (scaling up and tool use)

EXPERIMENT 6

Writing a Go algorithm

Now the network is far too large to write by hand: a 243-512×6-82 policy for 9×9 Go, 1,480,274 weights, all zero at the start. Opus has a Python sandbox (up to 120 runs) to compute the weights from its own design. Depending on the budget, it also gets 0, 10, 25 or 50 passes, each of which either plays its current network against practice opponents or runs it on chosen positions. Training, search and running the network outside a pass are forbidden.

EXPERIMENT 7

Which language model is sycophantic?

Two fine-tunes of Gemma 3 270M are built from the same data, seed and schedule. One learned to give the correct answer whatever the user guessed; the other learned to agree with the user's guess. Given only the two checkpoints, which is which, and where does the difference live? The original found that Astra was at chance from the weights alone across four attempts. With an attention tool, which returns attention patterns but no outputs, it got all three pairs right.

The fine-tuned models were never released, so I retrained all six with the released code, unchanged, and checked their behaviour against the released evaluation:

Status: Opus's conversations are running: the attention-tool round and round 4 in one stream, weights-only rounds 1–3 in another. If Opus, like Astra, is at chance from the weights alone, that negative result is as informative as a positive one. If it beats chance, that would be a real difference between the models.

EXPERIMENT 8

Make a language model better at math

The headline experiment. With a Python kernel over Qwen3.5-0.8B's weights and a budget of 10, 25 or 50 forward passes, Astra found the weights that make the model loop in its reasoning. It fixed them by editing 0.016% of the weights, raising MATH-500 from 7.9% to 48.1% at its largest budget. What I have learned so far

The sparks are not one model's quirk. On the five experiments that need no tools or very few, a second frontier model, from a different lab and with a different training stack, reaches the same qualitative results as Astra. It names games and shapes from raw weights, repairs a network with a one-shot edit, and writes working game policies from zero. The numbers are close too: Breakout 512 against 517, and 1,024 of 1,024 car episodes for both.

Opus is less confident, and often rightly so. Its confidence on the open-answer tasks is 20–40 points lower than Astra's, while still correct. On Experiment 3 its corpus probabilities hover near 0.5, which fits how often it is wrong.

Running a tool-trained model with its tools off has a failure mode. Twice in Experiment 3, Opus produced an analysis without running anything, once by writing imitation tool calls. These answers were not grounded in the weights. Any comparison of this kind needs to report such runs separately, as I do here.

Scaling up is where the models separate, so far. The one large-network result in yet, Go without passes, favours Astra clearly. Whether passes close that gap, as they did for Astra, is the next thing to watch.

Logs

Everything behind this page is at github.com/sidd20228/wsp-opus, laid out like the original logs. There is one folder per experiment with:

  • every prompt sent and every reply received;
  • every turn's raw event stream and tool-use audit;
